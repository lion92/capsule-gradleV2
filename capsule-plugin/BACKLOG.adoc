=== 🔍 EPIC CAP-PROVENANCE — Audit context anti-hallucination (contexte augmenté)

_Vision_ : Le LLM génère des speaker notes à partir d'un contexte augmenté
multi-canal (EAGER + RAG + Graphify + Docs + Scenario). L'auteur doit
vérifier l'ancrage : quel canal a nourri quelle partie, avec combien de
chars/tokens, depuis quels fichiers sources ? Sans provenance, le LLM peut
halluciner en s'appuyant sur un canal vide et l'auteur n'a aucun moyen de

_Décisions architecturales (US-0, Session 107)_ :

. *Pas de nouveau domaine* — `ContextProvenance` + `ProvenanceSource` +
  `ProvenanceTracker` rejoignent `capsule.context` (existant, 6 fichiers).
  La provenance est un artefact compagnon du contexte augmenté, pas une
  responsabilité distincte. Pattern CAP-SPD (extension capsule-local, pas N0).

. *`ProvenanceSource` data class immutable* — `fileName: String`, `chars:
  Int`, `tokens: Int`. Un canal peut avoir N sources (EAGER = N fichiers,
  DOCS = N fichiers, RAG/Graphify = 1 source "injected", SCENARIO = 1
  fichier). Invariant : `chars >= 0`, `tokens >= 0`. Pas de `init` fail-fast
  (les valeurs sont calculées, pas user-input).

. *`ContextProvenance` data class immutable* — `channels: List<ProvenanceChannel>`.
  `ProvenanceChannel` data class — `channel: String` (EAGER/RAG/GRAPHIFY/DOCS/
  SCENARIO), `sources: List<ProvenanceSource>`. Aggregate `totalChars(): Int`,
  `totalTokens(): Int`. `toJson(): String` (Jackson `ObjectMapper` +
  `INDENT_OUTPUT`, schema `{ "channels": [...], "totalChars": N, "totalTokens":
  M }`). Pas d'invariant fail-fast (une provenance vide est légitime —
  contexte vide).

. *`ProvenanceTracker` mutable accumulator* — PAS un object pur (accumule
  state pendant le build). `trackChannel(channel: String, sources:
  List<ProvenanceSource>)`, `build(): ContextProvenance`. Construit par le
  task, passé au builder. Pattern : tracker mutable + snapshot immutable
  (`build()` gèle l'état). Le builder ne possède pas le tracker — il le
  nourrit via callback/lambdas. Décision : le *task* construit le tracker
  et le passe au builder, car le task connaît les sources (eagerFiles,
  docsFiles, scenarioFile) que le builder a déjà flattées. Le builder
  signale au tracker quels canaux sont non-empty (après budget+filter), le
  task enregistre les sources par canal.

. *`CapsuleContextBuilder.build()` étendu — tracker optional* — signature
  `build(composite, budget, scenarioSection = "", tracker:
  ProvenanceTracker? = null): CapsuleContext`. Quand `tracker != null`, le
  builder signale les canaux non-empty après budget+filter (`tracker.
  trackChannel("EAGER", ...)` etc.). Backward compat : `tracker = null`
  (défaut) → aucun tracking, tests existants inchangés. Le builder ne
  calcule PAS les sources — il valide quels canaux ont survécu au budget,
  le task fournit les sources (le builder n'a pas accès aux File objects).

. *Wiring `CollectCapsuleAugmentedContextTask`* — construct `ProvenanceTracker`
  avant `build()`, passe au builder, récupère `tracker.build()`, écrit
  `provenance.toJson()` dans nouveau `@OutputFile provenanceFile: RegularFileProperty`
  (`build/capsule/context-provenance.json`). Tracking des sources par canal :
  - EAGER : `eagerFiles.files.sortedBy { it.name }` → N `ProvenanceSource(
    fileName = file.name, chars = file.readText().length, tokens =
    ContextChannel.estimateTokens(file.readText()))`.
  - RAG : 1 source `ProvenanceSource(fileName = "rag-injected", chars =
    ragContent.length, tokens = estimateTokens(ragContent))` si non-blank.
  - Graphify : 1 source `ProvenanceSource(fileName = "graphify-injected",
    ...)` si non-blank.
  - DOCS : `docsFiles.files` (ou `docsContent` legacy si pas de globs) → N
    sources.
  - SCENARIO : `scenarioFile.files.firstOrNull()` → 1 source si résolu.
  Le task ne tracker QUE les canaux non-empty après build (le builder
  signale quels canaux ont survécu). Un canal budget-tronqué à 0 est skippé.

. *Pas de config, pas de DSL, pas de 4 sources* — provenance est *always-on*
  (cheap : pas de LLM, pas de réseau, pas de FFmpeg, Jackson serialize <
  1ms). Pas de `CapsuleExtension` property, pas de `CapsuleConventions`
  champ, pas de `pushConfigIntoExtension` change, pas de `mergeProvenanceConfig`.
  Pas de `ContextConfig` champ. Décision : la provenance est un artefact
  *diagnostic*, pas une feature configurable. Toujours écrit compagnon de
  `augmented-context.txt`. L'auteur peut l'ignorer, pas la désactiver.

. *Économie d'encre (AGENT.adoc)* — `provenanceFile` est `@OutputFile`
  déclaré, le task est UP-TO-DATE quand `augmented-context.txt` l'est (même
  task, mêmes inputs). Pas de re-serialize inutile. Pas de probe (la
  provenance est calculée pendant le build, pas re-probée après).

. *JSON format* — Jackson `ObjectMapper` + `SerializationFeature.INDENT_OUTPUT`
  (lisibilité pour l'auteur). Pas de YAML (JSON est le format d'audit
  machine + humain). Schema :
  `{ "channels": [{ "channel": "EAGER", "sources": [{ "fileName":
  "INDEX.adoc", "chars": 1200, "tokens": 300 }] }], "totalChars": 4500,
  "totalTokens": 1100 }`. Pas de timestamp (la provenance est régénérée à
  chaque build, pas une archive historique).

. *Cucumber runner dédié* `CapsuleProvenanceCucumberRunner` (pattern S-082
